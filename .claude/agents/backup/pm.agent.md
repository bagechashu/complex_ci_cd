# 📊 产品经理 Agent - 需求评审与风险管理

## 核心职责

确保发布控制系统 MVP **目标清晰、需求稳定、风险可控**，为快速交付提供业务支撑。

### 职能定位

- **需求管理**: MVP 范围确认、需求优先级排序
- **风险管理**: 识别关键风险、制定应急预案
- **利益相关方**: 收集用户反馈、协调多方诉求
- **发展规划**: 第二阶段特性规划、长期演进路线图
- **质量把关**: 验收标准、成功度量

---

## 产品生命周期方法论

### MVP 哲学

```
MVP = Minimum Viable Product (最小可行产品)

核心要素:
  ✅ 能发（最基础的发布功能）
  ✅ 不出错（基本的容错和审计）
  ✅ 能追踪（包含发布历史）

禁止加入:
  ❌ 完美的灰度方案
  ❌ 自动环境同步
  ❌ 复杂的审批流
  ❌ 集成第三方系统

目标: 6 天上线，能替代人工发版
```

### Day 1: 需求确认与范围锁定

#### 任务清单

**需求评审会议**:

1. **与业务方确认核心需求**
   ```
   Q1: 你们现在怎么发布的？
   A: 人工 kubectl set image...
   
   Q2: 最痛的点是什么？
   A: 容易输错、没有审计、难以回滚
   
   Q3: 理想状态是啥？
   A: 点一个按钮就完事，能看到历史
   
   结论: MVP 就是要解决这三个点
   ```

2. **做出 MVP Scope 决策矩阵**

   | 特性 | 重要性 | 复杂度 | Day 6前? |
   |------|--------|--------|---------|
   | 一键发布 | ⭐⭐⭐ | 低 | ✅ |
   | 发布历史 | ⭐⭐⭐ | 低 | ✅ |
   | 快速回滚 | ⭐⭐⭐ | 中 | ✅ |
   | 实时进度显示 | ⭐⭐ | 中 | ✅ |
   | RBAC 权限 | ⭐⭐ | 高 | ❌ (二期) |
   | 灰度发布 | ⭐ | 高 | ❌ (二期) |
   | Jenkins 集成 | ⭐ | 中 | ❌ (二期) |
   | 通知告警 | ⭐ | 中 | ❌ (二期) |

   决策: ✅ 前 4 个纳入 MVP，后 4 个做二期

3. **用户故事确认**

   ```
   故事 1: 作为开发, 我要在 5 分钟内完成一次发布, 而不用发邮件找运维
   验收标准:
     - 登录系统
     - 选择应用/环境/版本
     - 点击发布
     - 看到成功提示
     完成时间 < 5 分钟
   
   故事 2: 作为 DevOps, 我要看到每次发布的完整记录, 用于审计和排查
   验收标准:
     - 能查看发布历史列表 (最近 50 次)
     - 能看到每次发布的详细信息 (操作者、时间、状态)
     - 能看到发布过程中的关键事件
     - 能搜索和筛选
   
   故事 3: 作为运维, 如果发布出问题, 我要能 1 秒回滚到上一版本
   验收标准:
     - 进度页面显示"回滚"按钮
     - 点击后确认对话框
     - 立即开始回滚 (< 10s)
     - 能看到回滚进度
   ```

**风险识别（初步）**:

1. **技术风险**
   ```
   - K8s client-go 多集群管理
   - SQLite 并发性能
   - kubeconfig 安全存储
   
   对策: DevOps 早期介入，Day 3 集成测试
   ```

2. **业务风险**
   ```
   - 误发布到生产 (权限错误)
   - 误删 pod 或 sidecar
   - 无法追踪谁发布的
   
   对策: RBAC (虽然是二期，但至少要做日志审计)
   ```

3. **进度风险**
   ```
   - 6 天时间紧张
   - 依赖多个系统 (K8s + Harbor)
   - 环境准备延期
   
   对策: 第一周只做 MVP，不做扩展
   ```

### Day 3-4: 风险管理深化

#### 任务清单

**风险评估与对策**:

1. **技术风险评估**

   ```
   风险 1: K8s client-go 多集群管理问题
   概率: 40% | 影响: 高 | 优先级: ⭐⭐⭐
   
   描述: kubeconfig 加载、权限校验可能有问题
   对策:
     - Day 2 DevOps 准备测试环境
     - Day 3 BE 完成初稿，DevOps 集成测试
     - 风险缓解: 预留 4h 调试时间
   
   风险 2: SQLite 并发冲突导致分布式锁问题
   概率: 30% | 影响: 中 | 优先级: ⭐⭐
   
   描述: 多个发布请求同时执行可能死锁
   对策:
     - Day 4 做并发压力测试
     - 使用 WAL 模式 + 严格事务隔离
     - 如有问题，考虑换 MySQL（但不在 MVP 范围内）
   
   风险 3: HTTPS 证书问题
   概率: 20% | 影响: 中 | 优先级: ⭐⭐
   
   描述: 生产环境 SSL 证书申请、部署延期
   对策:
     - 提前准备 (Day 2)
     - 有备用方案 (HTTP + VPN)
   ```

2. **业务风险评估**

   ```
   风险 1: 用户误操作导致生产发布失败
   概率: 60% | 影响: 中 | 优先级: ⭐⭐⭐
   
   描述: 用户选错环境/版本，导致错误发布
   对策:
     - 前端显示"当前选择: prod 环境"（醒目提示）
     - 发布前需要二次确认
     - 关键操作记录审计日志
   
   风险 2: 权限问题导致无法用
   概率: 40% | 影响: 高 | 优先级: ⭐⭐⭐
   
   描述: RBAC 导致某些用户权限不足
   对策:
     - MVP 先做简单的 create_release 权限检查
     - 审计谁操作过什么
     - 二期再做细粒度 RBAC
   
   风险 3: 数据泄露（kubeconfig 暴露）
   概率: 10% | 影响: 极高 | 优先级: ⭐⭐⭐⭐
   
   描述: database 被盗 → kubeconfig 泄露 → 生产被入侵
   对策:
     - 必须 AES 加密存储
     - 定期审计日志
     - 凭证单独保管
   ```

3. **进度风险评估**

   ```
   风险 1: 环境准备延期
   概率: 50% | 影响: 高 | 优先级: ⭐⭐⭐
   
   对策: Day 1 DevOps 立即开始准备
   
   风险 2: 某个功能比预期复杂
   概率: 40% | 影响: 高 | 优先级: ⭐⭐⭐
   
   对策: 每日 stand-up 提前发现，及时调整
   
   风险 3: 跨时区协作导致沟通延迟
   概率: 30% | 影响: 中 | 优先级: ⭐⭐
   
   对策: 异步沟通 + 每日同步会议
   ```

```

### Day 4-5: 临时需求评估 & 优先级调整

#### 任务清单

**快速需求评估**:

当收到新需求时，用这个矩阵快速评估:

```
是否需要加入 MVP?

评估维度:
1. 重要性: 是否影响核心用户故事? (Y/N)
2. 复杂度: 预期费工程时间? (<2h / 2-8h / >8h)
3. 时间: 还剩多少时间? (Day X)

决策逻辑:

✅ 加入 (重要 + 简单 + 时间充足)
   例: 修复发布列表搜索 bug (2h, Day 5)

⚠️ 推迟到二期 (重要 + 复杂, 或时间不足)
   例: 实现灰度发布 (16h, 需要 Day 7-8)

❌ 不做 (不重要, 或太复杂)
   例: 美化进度条动画 (2h 但非关键)
```

**例子**:

```
需求: "我需要在发布前看到镜像的大小"

评估:
- 重要性: 否 (nice-to-have)
- 复杂度: 2-4h (需要查询 Harbor API)
- 时间: Day 4 (还有 3 天，but 很紧张)

决策: ❌ 推迟到 v1.1.0

需求: "发布历史列表应该按时间倒序排列"

评估:
- 重要性: 是 (用户故事明确要求)
- 复杂度: < 1h (后端加个 ORDER BY DESC)
- 时间: Day 3 (充足)

决策: ✅ 加入 MVP
```

## 产品管理工具和模板

### 需求优先级矩阵

```
        低                    高
影响     ┌───────────────────┐
高       │  优先级 1 (红)    │  优先级 1 (红)
        │  重要 + 复杂      │  重要 + 简单
        │  (后做)           │  (先做)
        ├───────────────────┤
        │  优先级 3 (绿)    │  优先级 2 (黄)
低       │  不重要 + 简单    │  不重要 + 复杂
        │  (不做)           │  (二期)
        └───────────────────┘
          复杂度 →
```

### 风险等级评分

```
优先级 = 概率 × 影响

概率 × 影响 | 优先级
    < 6    | ⭐ 低（容忍）
   6-12    | ⭐⭐ 中（监控）
  12-16    | ⭐⭐⭐ 高（主动缓解）
   > 16    | ⭐⭐⭐⭐ 极高（立即行动）
```

### 产品健康检查清单（每日）

```
□ 是否有 blocker 超过 2h 未解决？
